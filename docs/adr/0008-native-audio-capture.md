# ADR 0008: Expo Audioでバックグラウンド録音と実音声再生を行う

Date: 2026-10-04

## Status

Accepted

採用確認: 2026-10-04 のチャットで、ユーザーがロック中・他アプリ使用中の録音継続を必須とし、実装計画に対して「IMPLEMENT THIS PLAN」と指示した。

## Context

旅行中は録音画面を見続けず、必要な場面で録音を開始・停止・再開する。承認済みUIの録音操作を実ファイルへ接続し、歌詞の元会話と完成曲を実際に再生する必要がある。[ADR 0003](0003-expo-app.md)に従いExpo SDKに対応するネイティブ機能を使用する。

## Decision

録音と再生には`expo-audio`を使用し、SDK対応の依存をExpoのインストール手順で揃える。録音器は画面ごとに作り直さずアプリの上位で保持する。[音声エンジン](../../src/platform/useAudioEngine.native.ts)に開始・停止・再生操作を集約する。

マイク権限とネイティブの準備が済んだ時点で開始日時を決め、保存先URIを含む録音中メタデータを永続化してからキャプチャを開始する。停止でファイルを確定し、再開は新しいファイルを作る。UI上の下書きは継続するが、停止前後を1つの連続録音ファイルとして扱わない。画面からの退出は停止と保存を待ち、OSによる画面ロックや他アプリへの移動では録音を止めない。

[設定](../../app.json)でバックグラウンド録音を有効にし、実行時にも録音用Audio Modeを設定する。AndroidはForeground Serviceと録音通知、iOSは音声のBackground Modeを使用する。ネイティブ設定を反映したdevelopment buildを実機で確認する。Expo GoやWebの表示だけをバックグラウンド録音の検証としない。[Expo Audioの公式仕様](https://docs.expo.dev/versions/v57.0.0/sdk/audio/)を参照する。

録音時間・ファイルサイズは実ファイルから取得する。60分は生成入力の上限と連続録音の検証条件であり、録音を無通知で自動停止する時間ではない。通話などのネイティブ割り込みを中断状態として扱い、自動で録音を再開しない。起動時の復旧は[ADR 0009](0009-local-durable-drafts.md)に従う。

元会話の再生位置は元ファイル内の区間時刻、完成曲のシーク位置は生成曲の時刻として分ける。元会話の区間再生を曲のシークとして扱わない。

## Consequences

- 利点: 承認済みの開始・停止・再開操作を維持し、端末がバックグラウンドでも会話を記録できる構成になる。停止単位のファイルが元会話の追跡と復旧の単位になる。
- 受け入れる欠点: 権限、OS、端末、通話割り込みに挙動が依存する。強制終了時のファイル確定や自動再開は保証できない。Webではネイティブ録音・音声取り込みを無効にする。

iOS / Android実機で、60分の録音、画面ロック、他アプリ使用、通知からの停止、割り込み、停止後の再開、元会話の区間再生を確認する。これらの実機検証が終わるまで、録音品質・継続性を確認済みとは扱わない。
