# 音声から曲生成までの費用概算

[ドキュメントの目次](README.md)へ

確認日: 2026-10-12。現行のモデル・構成を前提にした概算。

## 1・10・100・1000回の目安

**2分の録音から約3分の曲を作る場合、1回約15円、1000回で約1.6万円が目安。** エミュレータとPlay内部テストは同じバックエンドとモデルを使うため、同じ入力・操作なら費用の考え方も同じ。

「1回」は、新しい録音を文字起こしし、歌詞を1回作成・確認し、曲を1回生成して保存・再生まで成功すること。再生成や失敗による追加の有料試行を含めない。以下は**同じ月に実行し、生成物を1か月保存する**場合の新規利用分。無料枠を他の利用で消費していないと仮定する。

| 成功回数 | AI API | 基盤の増分費用 | 合計（USD） | 円換算の目安 |
| :--- | ---: | ---: | ---: | ---: |
| 1回 | $0.095 | 約$0.002 | **約$0.097** | **約15円** |
| 10回 | $0.95 | 約$0.017 | **約$0.97** | **約145円** |
| 100回 | $9.50 | 約$0.17 | **約$9.67** | **約1,450円** |
| 1000回 | $95.00 | 約$12.51 | **約$107.51** | **約16,126円** |

円換算は予算計算用の **1 USD = 150円** を使用した固定例で、現在の為替相場ではない。合計は丸める前の金額から計算。税・決済時の換算差、開発・配布の固定費は含めない。余裕を約20%持たせるなら、順に **$0.12 / $1.20 / $12 / $130**（約18円 / 180円 / 1,800円 / 19,500円）を目安にできる。

1000回の実負荷・実請求は未測定。現在のCloud Runは最大1インスタンス・同時処理1で、Cloudflareにも日次の無料枠があるため、月内で分散して処理する前提。短時間に1000回を通せるという保証ではない。

## AI費用の根拠

### 実際に成功した2件

[2026-10-12の通し検証](audio-pipeline-verification.md#2026-10-12-エミュレータ内部テストv5の通し生成とネイティブ再生)で記録した値を使う。

| 環境・録音時間 | 文字起こし | 歌詞作成 | 曲生成 | AI合計 |
| :--- | ---: | ---: | ---: | ---: |
| 開発エミュレータ・90秒 | $0.008036 | $0.001939 | $0.080000 | **$0.089975** |
| Play内部テストv5・120秒 | $0.010830 | $0.003945 | $0.080000 | **$0.094775** |

これはAPIのusageを料金表へ換算した**台帳上の見積もり**で、Googleの請求明細との照合済み実費ではない。表の2分ケースは後者を丸めた **$0.095 / 回** を採用した。保存応答からの文字起こし回復は、新たなGoogle POSTを行わず元の試行を再利用した。

### 現行モデルの単価

[Googleの公式料金表](https://ai.google.dev/gemini-api/docs/pricing)の有料・Standard単価を2026-10-12に確認した。無料のAI枠、Batch、キャッシュ割引は計算に使わない。

| 段階 | モデル | 単価（USD） |
| :--- | :--- | :--- |
| 文字起こし | `gemini-3.5-transcribe` | 入力100万tokensあたり$2、出力100万tokensあたり$12。Googleの標準例は入力・出力合計で約$0.005 / 音声1分 |
| 歌詞作成 | `gemini-3.5-flash-lite` | 入力100万tokensあたり$0.30、出力100万tokensあたり$2.50。出力はthinking tokensを含む |
| 曲生成 | `lyria-3.5` | Full Song 1曲あたり$0.08 |

単価と台帳計算の実装は [Googleアダプター](../pipeline/google.ts)を参照。文字数ではなくトークン数で変わり、日本語の発話量、発話ID・時刻等の入力、出力やthinkingの量で差が出る。現行の曲生成は約3分を指定している。

## 長い録音の場合

録音が長くなると主に文字起こしと歌詞入力が増える。以下は**AI APIのみ**のモデル計算で、長時間音声での通し成功・費用実測を表さない。

- 文字起こし: Googleの標準例に従い `$0.005 × 入力音声の分数`。標準例は入力25tokens/秒、出力175tokens/分を仮定しており、実際の日本語応答では変わる。
- 歌詞作成: 文字起こし・出典情報を含む入力を `1000tokens × 入力音声の分数`、出力とthinkingの合計を1360tokensと**仮定**する。式は `(入力tokens × 0.30 + 出力tokens × 2.50) / 1,000,000`。
- 曲生成: 録音時間によらず約3分の1曲を作り、$0.08を加算する。

| 入力音声 | AI / 1回 | AI / 10回 | AI / 100回 | AI / 1000回 |
| :--- | ---: | ---: | ---: | ---: |
| 2分（検証値を丸めた基準） | $0.095 | $0.95 | $9.50 | $95.00 |
| 10分（モデル計算） | 約$0.1364 | 約$1.364 | 約$13.64 | 約$136.40 |
| 30分（モデル計算） | 約$0.2424 | 約$2.424 | 約$24.24 | 約$242.40 |
| 60分（モデル計算） | 約$0.4014 | 約$4.014 | 約$40.14 | 約$401.40 |

25分を超える音声は分割して文字起こしする。分割ごとの出力や付加情報、歌詞入力の制限、前処理・話者照合の時間によって増減する。長い音声の基盤費用には下記の2分用保存量・送信量をそのまま適用せず、実際の容量と処理時間を使う。

## 基盤費用の計算条件

録音時間とCloud Runの課金時間は別。Google APIの応答を待つ間もCloud Runのリクエスト処理時間に含まれる。[ADR 0011](adr/0011-cloudflare-free-audio-runtime.md)と既存の[基盤概算](audio-pipeline-verification.md#2026-10-04の基盤費用の概算)に合わせ、今回も課金時間の合計を1回10分と仮定した。実測の平均処理時間ではない。

| 項目 | 2分の録音・約3分の曲に置いた条件 |
| :--- | :--- |
| Cloud Run | 東京・リクエスト課金・1vCPU / 1GiB・最小0。1回600秒、HTTP 10リクエストを仮定 |
| Cloud Run無料枠 | 月180,000vCPU秒、360,000GiB秒、200万リクエスト。請求先内の他の利用がない前提 |
| Cloud Run超過単価 | CPU $0.000024 / vCPU秒、メモリ$0.0000025 / GiB秒、リクエスト$0.40 / 100万件 |
| 外部送信 | 1回15MB（10進）を仮定。全量を$0.12 / GiBで計算し、通信無料分を引かない。実際の宛先・経路で単価が変わる |
| R2 Standard | 1回20MB（10進）を1か月保存。原音・64kbpsの分割音声・約4.35MBのMP3・Base64入りのGoogle原応答・メタデータを含む仮定 |
| R2無料枠と超過 | 月10GB-month、Class A 100万件、Class B 1000万件。保存超過は$0.015 / GB-month。GB-monthの切り上げを適用 |
| R2操作 | 1回Class A 20件、Class B 100件を仮定。1000回でも各無料枠内 |
| Workers / Workflows / D1 | 現行Freeプランのリクエスト・CPU・ステップ・保存・行数の枠内に収めると仮定し、追加料金0。実際のポーリング頻度やステップ数等は別途測定が必要 |

Cloud Runと通信は[Cloud Run料金](https://cloud.google.com/run/pricing)・[ネットワーク料金](https://cloud.google.com/vpc/network-pricing)、保存と操作は[R2料金](https://developers.cloudflare.com/r2/pricing/)を参照。Cloudflareの枠は[Workers](https://developers.cloudflare.com/workers/platform/pricing/)・[Workflows](https://developers.cloudflare.com/workflows/reference/pricing/)・[D1](https://developers.cloudflare.com/d1/platform/pricing/)で確認する。Workflows Freeには1日3000ステップ等の制限があり、無料枠を超えると処理が止まり得るため、回数だけで無料運用を保証しない。

成功回数を `N` とすると、月の増分費用を次で計算する。

```text
AI          = 0.095 × N
Cloud Run   = max(600 × N - 180000, 0) × 0.000024
            + max(600 × N - 360000, 0) × 0.0000025
通信        = (15000000 × N / 1073741824) × 0.12
R2保存      = max(ceil(0.02 × N) - 10, 0) × 0.015
合計        = AI + Cloud Run + 通信 + R2保存
```

リクエスト・R2操作は上記条件で無料枠内なので加算0。1000回ではCloud Run $10.68、通信約$1.6764、R2保存$0.15、基盤合計約$12.5064となる。同じデータを翌月も保存するなら、R2保存費用は毎月続き、新しい生成物の蓄積分も増える。

無料枠が既に使われている場合、Cloud Runの実行だけで約$0.0159 / 回（リクエストは別）が追加になる。R2も既存の保存量・操作数と合算し、課金単位の切り上げがあるため、上の合計を請求上限として扱わない。

## 再生成・失敗・現在の試行予算

- 確認済みの歌詞から別の曲を新しく生成する場合、音楽APIだけで **+$0.08 / 曲**。Cloud Run・通信・保存も増える。
- 歌詞を作り直す場合は歌詞APIが追加。端末での手動編集や保存済みの完成曲を再生する操作は、新しいAI生成を呼ばない。再生の保存アクセスは増える。
- 保存済み応答を同じ試行として回復できればAIの再課金は増えないが、Cloud Run・保存アクセスは増える。
- 送信後に結果不明となった試行や、応答検証に失敗した試行にも課金の可能性がある。成功した回数だけでは検証全体の支出を計算できない。有料POSTを自動で再送しない。
- 現行コードの予約額は、文字起こし1分割 **$0.60**、歌詞1回 **$0.50**、曲1回 **$0.08**。これは呼び出し前の予算確保・usage不明時の保守的計上で、正常にusageが取れた場合の一般的な1回費用とは別。25分単位の分割数が増えると予約も増える。

[ADR 0010](adr/0010-google-audio-quality-trial.md)の試行予算は累積$10。最後の検証記録では移管後のクラウド枠$8.733897に対し、成功分$1.528410・結果不明の予約$1.44を保持しており、予約込み残額は **$5.765487**。100回・1000回の表は将来の費用見積もりで、現行の残額ではその回数を実行できない。実行数を増やす場合は、ADRに沿って試行予算と無料枠・処理容量を見直す必要がある。

## 表に含めていない費用

Artifact Registryの既存・旧イメージ保管、GitHub Actions等のビルド、EAS配布ビルド、開発者アカウント、ログ、端末・通信回線、作業時間は別枠。生成回数に比例する費用と、月額・ビルド回数に依存する費用を合算して管理する。Artifact Registryは0.5GiB-monthの無料枠があり、超過保管は約$0.10 / GiB-monthだが、現在の全イメージの実請求は未照合。[公式料金](https://cloud.google.com/artifact-registry/pricing/)
