# ADR 0019: プライバシーポリシーを未認証で公開する

Date: 2026-10-07

## Status

Proposed

2026-10-07 にユーザーが Android 内部テスト開始に向けた準備を指示し、問い合わせ先に `rion.developer.apps@gmail.com` を指定した。文書と導線の実装を準備し、公開内容と外部反映は確認対象として残す。

## Context

Google Play 配布版は録音・登録した声・位置情報を扱うが、ログイン前と設定画面にプライバシーポリシーへの導線がない。特に [ADR 0017](0017-recording-location.md) のバックグラウンド位置権限には、アプリ内説明に加えて公開 URL、権限申告、利用を示す動画が必要になる。

## Decision

既存 Worker に静的 HTML の `GET /privacy` と `HEAD /privacy` を設け、Google ログインやデータベースの設定なしで読めるようにする。アプリのログイン画面とアカウント設定から同じ HTTPS URL を開く。認証を除外するのはこの文書の読み取りだけとし、通常 API・音声・位置情報・話者の保存境界は変えない。

文書には取得情報、位置の初期 OFF と条件付きのロック中取得、録音中は送信しないこと、歌詞準備時の送信、Google と Cloudflare による処理、アカウント削除と費用台帳の保持を現行実装に沿って記載する。問い合わせ先はユーザーが指定した窓口を使用する。

別の Web サイトを作る案は、内部テスト開始のために新しいホスティング先と配布設定を増やすため見送る。文書をアプリ内だけに表示する案は Play Console に登録する公開 URL を提供できないため見送る。

## Consequences

- 利点: ログインできない利用者も情報の扱いと窓口を確認できる。保存済みの個人データを公開せず、既存の API 配置とともに文書を更新できる。
- 受け入れる欠点: Worker の更新と可用性に文書の公開が依存する。固定された窓口・保存方針を、実装や運用の変更時にも照合する必要がある。文書の追加だけでは Play の位置権限承認を保証しない。

未認証での取得、HEAD、私有 API の拒否を自動テストで確認し、反映後に公開 URL とアプリからの導線を実際に開く。Play の権限申告と動画は配布時に別途確認する。
