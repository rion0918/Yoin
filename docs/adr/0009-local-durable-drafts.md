# ADR 0009: 下書きをSQLiteとDocuments内の音声ファイルで永続化する

Date: 2026-10-04

## Status

Accepted

採用確認: 2026-10-04 のチャットで、ユーザーがローカル保存と再起動時の復元を含む実装計画に対して「IMPLEMENT THIS PLAN」と指示した。

## Context

録音や歌詞確認の途中で画面を閉じても、保存済みの会話と下書きを失わない必要がある。キャッシュの一時ファイルやReactのメモリーだけでは、再起動後の復元に足りない。音声ファイルとアプリ状態は別々に保存されるため、停止・保存失敗・起動時の復旧を明示する必要がある。

## Decision

音声は`expo-file-system`のDocuments配下へ保存し、取り込んだ音声もキャッシュからDocumentsへコピーする。下書き、曲、処理状態、歌詞リビジョン、音声URIの参照は`expo-sqlite`のLibrary Documentに保存する。書き込みを直列化し、SQLiteの排他的トランザクションで更新する。[保存実装](../../src/platform/storage.native.ts)、[共有契約](../../shared/contracts.ts)、[SQLiteの仕様](https://docs.expo.dev/versions/v57.0.0/sdk/sqlite/)を参照する。

API接続先とテスター用トークンはネイティブで`expo-secure-store`に保存する。Googleの鍵は端末に保存しない。Webは表示・操作確認用のローカル状態を保存するが、トークンはセッションのメモリー内だけに保持する。

録音開始前に`pendingRecording`へクリップIDと保存先URIを記録する。停止後は実ファイルを検査してクリップを追加し、同じIDの重複追加を防ぐ。SQLiteへの保存が失敗した停止済みクリップは実行中のメモリーに保持し、新しい録音を始める前に保存を再試行する。

起動時に録音中表示を復元しない。未確定のURIを検査し、再生可能なら保存済みクリップへ回収する。回収できない場合は中断表示にし、URIを`recoveryFiles`に残して元ファイルを削除しない。[復旧処理](../../src/pipeline/library.ts)は参照を保持するが、壊れたファイルの修復や利用者向けの再検査画面は現在提供しない。

取り込んだ音声の録音日時・場所は、不明な場合に補わない。録音開始日時と、ファイルを取り込んだ日時を別の値として保持する。

## Consequences

- 利点: 通信前でも音声と下書きを保持し、再起動時に保存済みの状態を戻せる。生成に失敗しても元音声を保持できる。
- 受け入れる欠点: ファイルとSQLiteをまとめた1つのトランザクションはない。保存先を準備してから録音開始までの間隔、強制終了、端末容量不足、一時的な検査失敗は残る。回収できないファイルの参照保持は、音声の復元成功を意味しない。アプリ削除後の復元や端末間同期は対象外とする。

停止後の保存・再起動復元、保存失敗時の再試行、未確定ファイルの回収、回収失敗時のURI保持、二重回収を検証する。未確定ファイルを理由なく消去しない。
