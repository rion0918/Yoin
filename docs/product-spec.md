# プロダクト仕様

[ドキュメントの目次](README.md)へ

Yoinは、残した会話を確認・編集した歌詞から曲にし、元の会話と一緒に聴き返すアプリです。この文書は現在の実装の振る舞いを説明します。実際に確認できた範囲は[検証記録](audio-pipeline-verification.md#現在の確認状況)を参照してください。

## 録音から曲まで

| 操作 | 振る舞い |
| :--- | :--- |
| ライブラリで記録を作る | 名前入力なしで新しい下書きを開く。ライブラリと録音画面は白を基調にする |
| 録音を開始・停止・再開する | 停止ごとに音声ファイルを確定し、再開は新しいファイルを同じ下書きへ追加する |
| 録音画面から戻る | 録音中なら停止・保存を待つ。保存済み会話がある下書きは再開できる。音声も復旧対象もない空の下書きは破棄する |
| 音声を取り込む | 選んだ音声を端末内へコピーし、実時間とサイズを取得する |
| 仕上げる | 名前と音声を確認し、必要なら区間の場所を手入力する。送信後は文字起こしと出典付き歌詞案を準備する |
| 歌詞を確認・編集する | 元発話との対応を保持して歌詞を修正する。編集したリビジョンを曲生成に使用する |
| 曲を生成する | 保存された実音源を持つ曲をライブラリへ追加する。完成した曲の画面に色と背景を持たせる |
| 曲と会話を聴き返す | 歌詞の会話アイコンから元の会話区間を聴き、曲の再生位置を保持して戻る |

仕上げ中の下書きには録音や音声を追加できません。名前や音声がない状態では仕上げられません。接続先とトークンはライブラリの設定から入力します。

## 元会話との対応

- 文字起こしは音声ID、話者ラベル、元ファイル内の開始・終了時刻を持つ。
- 歌詞ブロックは元発話IDを保持する。存在しない元発話を出典にできない。
- 話者ラベルは仮ラベルで、人名を自動推測しない。
- 元会話の時刻と曲の再生位置は別々に扱う。歌詞と歌唱の時刻同期・歌詞ジャンプは現在の範囲に含まない。
- 出典が存在しても、歌詞の意味や実際の歌唱の一致は[品質評価](internal-testing.md#品質評価)で確認する。

## 日時と場所

録音開始日時と取り込み日時を別に保持します。取り込んだ音声の録音日時が不明なら、不明のまま扱い、ファイルの更新日時から補いません。表示する元会話の日時は録音日時・タイムゾーン・発話のオフセットから求めます。

場所は仕上げ前の手入力です。未指定は不明のまま扱い、GPSによる自動取得は実装していません。

## 入力と録音の制約

| 項目 | 上限・扱い |
| :--- | :--- |
| 生成へ送信する音声 | 下書きの合計60分以内 |
| 1ファイル | 100MiB以内 |
| APIが受付する形式 | MP4/M4A、MP3、WAV、AACの対応MIME形式。実ファイルをFFmpegで検査する |
| 送信 | 8MiB単位のmultipart。進行を保存して途中から再開する |
| 文字起こしの前処理 | モノラル16kHz・AACへ変換し、約25分単位に分割する（エンコード境界で最大1秒の許容） |

60分は生成入力の上限で、自動録音停止の時間ではありません。上限を超えた音声も端末に保持しますが、生成への送信は拒否します。

画面ロックや他アプリへの移動では録音を継続する設定です。通話などの割り込みは中断として扱い、自動で録音を再開しません。強制終了後は実ファイルを検査して復旧しますが、未確定・壊れた音声の復元は保証できません。

## 保存と失敗時の扱い

音声は端末のDocuments、下書き・歌詞・ジョブ等はSQLiteに保存します。送信・生成が失敗しても元音声の参照を保持します。読み取れない録音候補は復旧対象として残し、起動時に再検査します。アプリ削除後の復元や端末間同期は現在の範囲に含まれません。

生成処理はサーバーのジョブとして継続し、アプリを開き直すと保存された状態を取得します。有料APIの受付結果が不明なら照合待ちで停止します。再生成の連打による重複課金を避ける契約は[構成・設計](audio-pipeline-architecture.md#有料試行と結果回復)を参照してください。

## 対応端末と提供範囲

| 対象 | 用途 |
| :--- | :--- |
| Android development build | 録音・取り込み・保存・生成・再生の内部テスト対象。起動にはMetro接続が必要 |
| Web | 画面・操作の確認。ネイティブ録音・端末音声の取り込みは無効 |
| iOS | コードとexportの対象。iPhone実機での受け入れは未完了 |

認証は固定の所有者に対応する単一テスター用です。会員登録、ユーザーごとの分離、公開共有、利用者への課金、自動ジャケット生成は実装していません。AIモデルは品質検証候補で、完成品としての品質・商用利用可能性の確認は残っています。
