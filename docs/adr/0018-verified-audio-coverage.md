# ADR 0018: 音声の処理範囲を検証し、疑いがあれば確認を待つ

Date: 2026-10-07

## Status

Proposed

## Context

短い文字起こし応答が返っても、入力音声のほぼ全体を処理したように見える場合がある。分割manifestと保存済み音声の範囲を確認せず続行すると、音声の欠落や認識漏れを歌詞に反映できない。過去の応答喪失や再処理では、同じ音声への有料POSTを重ねない制約もある。[ADR 0008](0008-native-audio-capture.md)の原音・実時間を保つ判断、[ADR 0009](0009-local-durable-drafts.md)の復旧用参照、[ADR 0010](0010-google-audio-quality-trial.md)の累積予算と受付不明時の停止を前提とする。

## Decision

録音器・端末ファイル・サーバー検査の実時間を保存し、1秒または1%の大きい方を超える差を確認対象にする。FFmpegの `silencedetect` を初期値−50dBで実行して有音区間を記録し、文字起こし区間を前後2秒広げても、15秒以上の未認識範囲に5秒以上の有音が残れば歌詞作成前に `needs_audio_review` で同じWorkflowを最大30日待機させる。利用者は原音と保存済みの全文を確認してから、その文字起こしのSHA-256指紋を送って続行を承認する。

各分割の先頭・連続性・終端を最大1秒の境界許容で検証し、保存済みmanifestの入力ETag・変換版・R2オブジェクトを照合して再利用する。文字起こし結果の指紋には入力・モデル・認識設定を含め、別ジョブから同じ完了結果を再利用する。認識漏れの疑い、未完了応答、または欠落分割を有料の自動再送で補わず、原応答・部分結果・原音と予約額を保持する。

確認をせず歌詞へ進む方式は認識漏れを見逃すため採用しない。応答の短さだけで未認識と断定する方式は長い無音を誤検知するため採用せず、有音区間と発話区間を照合する。別モデルへの自動切替や音声の自動削除は行わない。

## Consequences

- 利点: 録音全体・分割・認識の範囲を追跡でき、疑いのある歌詞作成を止められる。結果再利用時の分割変換と有料認識を減らし、重複課金を避ける既存台帳を保てる。
- 受け入れる欠点: −50dBを超える雑音も有音として数えるため確認画面が余分に出る場合がある。15秒・5秒の規則は認識品質の証明ではなく、利用者の確認を完全に置き換えない。30日を過ぎたWorkflowは終了し、保存済み結果から新しい準備ジョブを始める必要がある。

この提案は[音声パイプライン](../audio-pipeline-architecture.md)の契約に反映する。採用確認前はProposedのままとし、実機録音・実APIの品質・約3分の歌唱は別途試聴して評価する。
