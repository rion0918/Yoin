# ADR 0021: 思い出の光の表紙と白い時間の帯を共通素材にする

Date: 2026-10-08

## Status

Proposed

2026-10-08のチャットで、ユーザーがさらにリッチなデザインへの刷新を依頼し、質問をせずデザイン判断を進めるよう指示した。個別の設計の採用確認はまだ行っていない。

## Context

[ADR 0020](0020-memory-led-ui.md)の実装は実会話と時間を中心にしたが、文字と線に偏り、完成した一日の魅力や触った感触が弱かった。入口・記録は白、完成した思い出だけ色を持つ既存制約の中で、複数画面に共通する素材と奥行きが必要になる。

## Decision

完成した思い出はオリジナルの抽象的な光の画像を表紙として使い、実際の日時・会話・参加者・場所で一日を識別する。画像は旅行写真ではなく装飾であり、思い出IDに応じた安定した切り取りだけを行う。記録と仕上げは白い帯を使い、保存クリップの実時間を帯の幅と区切りで表す。帯の高さは装飾であり、音量・分析進捗・再生位置には使わない。

白い紙面とグラファイトの文字・操作を共通にし、表紙は24、補助面は14、主操作は32の角丸を基準にする。記録の操作は下部に固定し、思い出詳細は表紙の穏やかなスクロール移動と歌詞・元会話の紙面をつなぐ。動きを減らす設定では新しい移動・出現・点滅を止める。

ベージュと金属色による高級感、汎用的な音楽ジャケット一覧、架空の旅行写真、即時文字起こしや同期歌詞の演出は見送る。既存の記録・非同期生成・音声・保存契約は維持し、表示のための依存追加はしない。

## Consequences

- 利点: 色・質感・時間の積み重なりが画面の魅力になり、会話と曲の関係を実データで辿れる。操作の場所を安定させながら画面ごとに異なる構図を持てる。
- 受け入れる欠点: 1枚の抽象画像を共有するため、切り取りが同じ思い出もある。画像は実際の情景を伝えない。ネイティブのスクロール、読み上げ、キーボード、実音声と生成の受け入れはブラウザー検証で代替できない。

設計・画像の生成記録は[リッチなUIへの刷新](../premium-ui.md)、確認した操作と画面は[検証記録](../../qa/premium-refresh/README.md)に残す。ADR0002・0003・0008・0009・0016・0017の契約は維持する。Discussionの投稿は依頼されていない。
