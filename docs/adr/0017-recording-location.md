# ADR 0017: 録音位置を端末取得し、クリップ単位で保存する

Date: 2026-10-06

## Status

Accepted

採用確認: 2026-10-06 のチャットで、ユーザーが初期OFF、場所の任意編集、未取得の場合だけ最初の座標までバックグラウンド取得する計画の実装を指示した。

## Context

録音、文字起こし、話者情報に加えて、会話があった場所を思い出の素材として保持する。位置情報は個人の行動を示し得るため、録音中の常時取得やサーバーへの逐次送信を避ける必要がある。既存の音声基盤は端末SQLite、Cloudflare Workers、D1、非公開R2であり、Firebaseは認証に使う。

Google Maps Platform の現在の公開料金表では Geocoding SKU に月10,000件の無料利用枠があり、その後の最初の有料帯は1,000件あたり5米ドルである。Geocoding API のポリシーは結果の保存・キャッシュを原則制限し、Place ID を例外としている。料金・条件は変更されるため、採用時には公式資料を再確認する。

- [Google Maps Platform 料金表](https://developers.google.com/maps/billing-and-pricing/pricing)
- [Geocoding API のポリシー](https://developers.google.com/maps/documentation/geocoding/policies)

## Decision

録音画面で初期OFFの明示的な選択を設け、許可された場合に限り、会話録音中にBalanced精度の位置を約60秒間隔で取得する。画面表示中の位置は端末メモリに保持する。画面ロック時点で有効な位置を一度も取得できていない場合だけ、バックグラウンド位置権限を許可した録音に限り、最初の有効な座標を得るまで約60秒間隔で取得する。最初の位置を保存したらバックグラウンド更新を停止し、すでに画面表示中に位置を得ている場合はロック中に取得しない。録音停止時もバックグラウンド更新を停止する。

位置をONにした時点で使用中の位置権限を要求する。バックグラウンド利用の目的と範囲を先に説明し、同意がある場合だけバックグラウンド権限を要求する。許可されない場合は画面表示中だけ位置を取得し、録音は続ける。バックグラウンドタスクで受け取った最初の座標はUID別SQLiteの一時テーブルへ保存し、画面復帰時または録音停止時に同じクリップの位置ルートへ統合する。録音中に位置をサーバー送信しない。音声停止時にクリップ別ルートとして所有者のLibrary Documentへ保存し、歌詞準備時に認証付きWorker APIから非公開R2へ送信する。D1には小さな要約と内容ハッシュのみを保存する。

画面表示中だけ取得する案と、ロック後に一度だけ取得を試して失敗時に停止する案を検討した。場所の自動表示に使える座標が得られる可能性を高めつつ、位置取得済みの録音でバックグラウンド更新を続けない条件付き取得を採用する。

場所名は端末Geocoderから市・区までを取得し、番地・建物・施設名を保存しない。APIキーと従量課金を伴う Google Geocoding API は今回は採用しない。Google APIを使う場合は、現行料金と結果保存制約に加え、利用規約・帰属表示の要件が追加されるためである。

歌詞準備時に、下書き全体の時系列上の開始・終了地点と、取得区間内の最長滞在地点を選んでから近接候補を統合し、場所名を解決する。解決結果（失敗時は名称なし）を含む送信内容と `preparedForUpload` をSQLiteへ保存してから送信する。起動時は準備済み・未送信のルートだけを再送し、準備前のルートは歌詞準備まで保持する。再実行でも確定した送信内容を変更しないため、サーバーの内容ハッシュによる重複防止を維持し、名称補完用の追加R2 PUT・D1更新を導入しない。

ルートは `locations/{uid}/{draftId}/{clipId}/location.json` に保存する。D1の `clips.location_summary_json` はnullableとし、位置要約を音声メタデータの再送比較から分離する。発話への位置対応は `clip.recordedAt + utterance.startMs` と同一取得区間内の最近傍サンプルで導出し、座標を発話に複製しない。

## Consequences

- 利点: 録音中の位置通信をなくし、位置の所有・削除をUID単位で既存の保存境界に合わせられる。位置拒否や取得失敗は録音と歌詞準備を妨げない。位置を一度も得られず画面がロックされた場合にも、最初の座標を得られる機会を残せる。
- 受け入れる欠点: バックグラウンド権限の追加で同意の手間が増える。初回座標を得る前に画面ロックが続くと、取得または録音停止まで位置更新を続けるため電池を使う。位置拒否、測位不可、タスク実行制約、強制終了では取得できない場合がある。端末Geocoderの名称や可用性はOS・端末に依存し、座標があっても場所名を得られない場合がある。Google APIより場所名の一貫性を保証しない。
- 1クリップ512サンプル、場所名問い合わせは下書きごとに最大3回、端末キャッシュは成功結果128件・30日とする。準備に失敗したルートは端末に保持し、次回起動時に一度再試行する。
- 導入順はアプリ設定と再ビルド、アプリ実装とする。D1 migrationとWorker更新は不要。実機での位置精度・長時間録音・ロック復帰は別途受け入れ確認する。
