# ADR 0029: 一致する保存済み曲だけを同じジョブで完成処理へ戻す

Date: 2026-10-13

## Status

Proposed

2026-10-13のチャットでこの実装計画の実施を指示された。計画に従い、品質受け入れと配布判断を分離し、記録はProposedに保つ。

## Context

Lyriaの完了済みMP3と承認済み歌唱テキストが保存されていたが、返却本文の[[A0]]等の構造マーカーを照合器が歌詞と扱い完成処理を停止した。追加生成では費用と承認済み入力が変わる。

## Decision

観測済みの[[英大文字1文字＋数字]]と既存の構造タグだけを除いて完全一致を要求する。任意の括弧内の説明や意味の類似で歌詞の相違を通さない。所有者・現在のジョブ・歌詞リビジョン・曲設定・成功済み試行・音源の存在とサイズを照合できる場合だけ、recover-musicで同じWorkflowを再開する。復旧経路は保存結果の読み出し、音源検査、完成曲の一意保存だけを行う。Google送信・新規予約・台帳更新・本文や出典IDの置換を行わない。応答喪失と二重操作は同じジョブIDを返す。受付不明・真の不一致・他ジョブは復旧しない。

## Consequences

既存音源を追加課金なしで完成できる。音源や保存結果が欠ける場合、利用者の再操作だけでは完了できない。ADR 0010/0011の予約保持と、ADR 0024の表示歌詞・読みの分離を維持する。復旧は歌唱品質の合格を意味しない。
