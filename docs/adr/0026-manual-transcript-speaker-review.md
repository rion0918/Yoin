# ADR 0026: 確認画面で未特定の発話へ話者を割り当てる

Date: 2026-10-13

## Status

Proposed

## Context

Googleの文字起こしには本文と時刻がある一方で、話者ラベルがない場合がある。現在の確認画面は原音と発話を表示するが、未特定の発話へ録音参加者を付ける操作がなく、確認後に歌詞を作れることも画面から分かりにくい。既存のD1発話行には `speaker_profile_id` と `speaker_name` があり、下書きと準備ジョブには選択参加者と固定したプロフィール情報が保存されている。

話者ラベルを推測で補わない方針は[ADR 0025](0025-unlabelled-transcript-review.md)、記録ごとに参加者を選ぶ方針は[ADR 0016](0016-memory-speaker-selection.md)に従う。

## Decision

文字起こし確認画面で、未特定の発話ごとにその記録で選択した参加者を割り当てられるようにする。APIは下書き所有者、対象発話、現在の文字起こしリビジョン、ジョブに固定された参加者を検証し、既存の発話列へ話者IDと名前を保存する。承認イベントには割当て後の文字起こし指紋を含め、Workflowはその状態を歌詞作成の入力として再読込する。

割当ては必須にせず、名前が分からない発話を未特定のまま歌詞へ含める選択も残す。未特定を直前の話者で埋める案は、誤帰属を隠すため採用しない。すべての発話への割当てを必須にする案は、録音だけでは話者を判別できない場合に歌詞作成を止めるため採用しない。

## Consequences

- 利点: 話者名が抜けた発話を利用者が修正でき、修正内容が歌詞作成へ反映される。新しい保存列やmigrationは不要。
- 受け入れる欠点: 利用者は原音を確認して話者を選ぶ必要がある。割当てを見送った発話は話者名なしで歌詞作成に進む。
- 確認: 選択済み参加者だけの保存、古い指紋の競合拒否、冪等な再送、割当て後の歌詞入力をAPI・Workflowテストで確認する。
