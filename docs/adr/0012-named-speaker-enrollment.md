# ADR 0012: 登録した声から話者名を識別する

Date: 2026-10-05

## Status

Proposed

## Context

文字起こしの話者分離は、クリップやチャンクごとの仮ラベルを返す。現在の契約だけでは、そのラベルが誰かを特定できず、別の会話へ同じ人の名前を表示できない。名前と声の登録、端末・サーバー間の保存、文字起こし後の照合を複数モジュールにまたがって追加する必要がある。

## Decision

1人ずつ名前と約20秒の声を登録し、Cloud Run上の `sherpa-onnx-node` と WeSpeaker ResNet34 LM ONNXモデルで声の特徴を抽出する。端末はプロフィール名・登録状態と、Documents内の登録音声参照をSQLiteに保存する。登録音声は認証付きAPI経由で非公開R2へ、特徴量とモデル版は所有者IDと共にD1へ保存する。

文字起こしをD1へ保存した後、チャンクごとに仮話者の非重複発話区間だけを使って登録済み特徴量と比較する。cosine similarity 0.65以上かつ次点との差0.10以上のときだけ名前を採用し、それ以外は仮ラベルを保持する。各準備ジョブの開始時点で登録情報を固定する。照合は有料文字起こしと独立したWorkflow段階として再試行できるようにする。

現行の仮ラベルだけを維持する方法では本人名を表示できないため、この拡張を提案する。モデルは [sherpa-onnxのspeaker recognition配布物](https://github.com/k2-fsa/sherpa-onnx/releases/tag/speaker-recongition-models)から取得し、WeSpeakerとモデル名・SHA-256を記録する。端末の録音前に1人以上のサーバー登録済みプロフィールを要求し、登録済みプロフィールがある端末はオフライン録音を許可する。

## Consequences

- 利点: 会話ごとに入れ替わる仮ラベルを登録名へ置き換え、登録音声を会話下書きから分離して永続化できる。モデル照合の再試行で文字起こしの有料POSTを再送しない。
- 受け入れる欠点: 登録音声と声の特徴量という機微な情報を保存するため、非公開保存、所有者確認、明示的削除が必要になる。モデル推論をCloud Runへ追加し、イメージサイズと処理時間が増える。
- 未確認: WeSpeakerの英語中心の公開モデルで日本語会話をどの程度正しく識別できるか、0.65 / 0.10の基準が適切かは実機で評価する。十分な長さの日本語発話で90%以上、未登録話者を誤割当しないことを受け入れ条件とする。
- 適用順: 自動テスト後にD1移行、Cloud Run、Worker、アプリの順で反映する。AI累積予算と未確定予約は既存台帳のまま保持する。
