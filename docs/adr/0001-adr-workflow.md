# ADR 0001: Nygard形式のADRを開発フローに組み込む

Date: 2026-10-04

## Status

Accepted

採用確認: 2026-10-04 のチャットで、ユーザーが `pop-reminder/` を参照して「このフォルダで採用しているadrをまずは構築してください」と指示した。

## Context

Yoin は UI プロトタイプから本実装へ進む段階にあり、技術や構造に関する判断を残す場所がまだない。今後の変更で採用理由や受け入れた欠点を確認できるよう、ユーザーが指定した `pop-reminder/docs/adr/` と同じ運用を整える必要がある。

## Decision

短い Nygard 形式の ADR を `docs/adr/` に保存し、開発フローに組み込む。1件につき1つの判断を、日本語の `Status / Context / Decision / Consequences` と Date で記録する。

[運用ガイド・一覧](README.md)と[テンプレート](template.md)を用意し、[ルートのエージェントガイド](../../AGENTS.md)から参照する。作業前に関連 Accepted ADR を読み、新しい判断は Proposed として記録し、ユーザーの採用確認後に Accepted へ変更する。採用済み判断の変更は後継 ADR と相互リンクで残す。

相談はチャット・PR・必要に応じた Discussion で行い、決定本文はリポジトリで管理する。外部への投稿は個別の指示を受けて行う。

参照元と同じ形式を採用することで、既存の記録方法を Yoin でも使えるようにする。別形式の比較検討は今回行っていない。

## Consequences

- 利点: 実装と同じリポジトリで、判断の背景・理由・欠点を確認できる。エージェントも変更前に採用済み判断を参照できる。
- 受け入れる欠点: 一覧・状態・関連リンクを手動で更新する必要がある。自由記述のため、理由や欠点が十分に記録されているかレビューで確認する必要がある。

参照が行われなくなった場合や、記録・リンクの維持が継続的な負担になった場合は、この運用を見直す。
