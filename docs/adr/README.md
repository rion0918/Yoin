# ADR 運用ガイド・一覧

ADR（Architecture Decision Record）は、1つの重要な判断について、背景・採用理由・受け入れた欠点を短く残す記録です。開発者とエージェントが変更前に読み、将来その判断を見直すときに使います。

Accepted の記録が現在の採用済み判断です。Proposed は提案段階であり、採用済みとして扱いません。記録の追加・状態変更時には、この一覧も更新します。

番号は `0001` からの連番とし、削除・却下・置き換え後も再利用しません。次の記録は `0003-<short-title>.md` です。

## 作業前に読む

1. この一覧から、変更対象に関係する Accepted ADR を読む。
2. 現行コードとテスト・設定を確認し、その判断に従った変更か、新しい判断が必要かを整理する。
3. 実装と ADR が矛盾している、または判断を変える必要がある場合は、変更前に理由を提示してユーザーに相談する。

ADR は判断の理由を説明します。実装の詳細はコードや設計ガイド、検証はテストやビルドなどの実行可能なチェックで確認します。食い違いを見つけても、ADR やチェックを黙って書き換えて解消しません。

## 記録する判断

次のいずれかに当てはまる判断を記録します。

- 覆すと複数のモジュールに影響する技術・依存方向・データ所有権の選択。
- プロジェクトに長く効く制約や、受け入れるトレードオフ。
- 後から「なぜこれを選び、他案を見送ったのか」を知る必要がある選択。

小さな修正や既存判断に従う変更は、関連 ADR と変更理由を PR に記載します。ADR を追加しない場合は、その理由を短く残します。

## 記録する流れ

1. 相談が必要な判断は、チャット・PR・必要に応じた GitHub Discussions で背景と選択肢を検討する。Discussion は全 ADR の必須手順ではない。
2. [テンプレート](template.md)を複製し、未使用の連番と英小文字・ハイフンの短い名前で保存する。見出しは `Status / Context / Decision / Consequences`、本文は日本語、Date は作成日とする。
3. Proposed として、背景、採用したい案と理由、実際に検討した他案と見送り理由、利点と受け入れる欠点を書く。コードから分かる事実と理由の推測を区別し、未確認の検討経緯は補わない。
4. PR に関連 ADR と、利用した Discussion へのリンクを記載する。Discussion を利用した場合は、そちらからも ADR・PR へリンクする。エージェントによる投稿は個別の指示を受けて行う。
5. ユーザーの採用確認後に Accepted へ変更し、Date を採用日にする。採用確認のコメントや PR がある場合は Status 節にリンクを残す。チャットで確認した場合は、確認日と指示内容を残す。すでに確認済みの判断は、その確認を記して Accepted として記録できる。

Decision には結論・採用理由・実際に見送った選択肢をまとめます。Consequences には利点と欠点を両方残し、必要なら確認方法や見直す条件を添えます。詳細な仕様や手順は適切な文書へリンクし、1件に複数の判断を詰め込みません。

## 状態と見直し

| Status | 扱い |
| :----- | :--- |
| Proposed | 提案中。採用前に内容を相談・修正する。 |
| Accepted | ユーザーが採用を確認した判断。 |
| Rejected | 見送った提案。Decision に却下理由を残す。 |
| Deprecated | 代替する判断がなく、使用をやめた記録。Status に廃止理由を残す。 |
| Superseded | 新しい Accepted ADR で置き換えた記録。Status に後継 ADR へのリンクを残す。 |

Accepted になった判断本文は書き換えません。状態変更・関連リンク・誤字の修正は可能です。判断を変える場合は新しい Proposed ADR を作り、Context に旧 ADR へのリンクと見直す理由を書きます。新しい判断の採用確認後に旧記録を Superseded へ変更し、相互リンクを残します。

変更対象に関連する ADR を読むタイミングで、背景や制約が今も成り立つかを確認します。

| ケース | 行うこと | PR に残すもの |
| :----- | :------- | :------------ |
| 既存判断に従う変更 | 関連 Accepted ADR を確認する。 | 関連 ADR と、新規 ADR が不要な理由。 |
| 新しい技術選定 | 必要なら相談し、Proposed ADR を作る。 | ADR と、利用した Discussion のリンク。 |
| 判断の置き換え | 旧判断と変更理由を相談し、後継 ADR を作る。採用後に相互リンクする。 | 旧・新 ADR と、利用した Discussion のリンク。 |

## Discussions との使い分け

Discussion には相談とコメントの経緯を残し、決定の本文はこのディレクトリで管理します。相談には「背景と判断したいこと」「選択肢と懸念」「関連リンク」を記載します。決定本文を両方で維持したり、自動同期したりする運用は導入しません。

この運用は、ユーザーが指定した `pop-reminder/docs/adr/` を基にしています。参照元の番号履歴・Discussion URL・アプリ固有の技術選定は引き継ぎません。
