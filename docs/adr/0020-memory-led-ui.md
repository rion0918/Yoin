# ADR 0020: 一日の時間と出典の言葉をUIの共通表現にする

Date: 2026-10-07

## Status

Proposed

2026-10-07のチャットで、ユーザーが全面刷新を依頼し、デザイン判断を委任した。個別の設計の採用確認はまだ行っていない。

## Context

既存の本実装はジャケット一覧、マイクと時間、生成状況、歌詞と元会話の3画面とシートを持つ。今回の要件は「写真に残らない思い出を、その日の一曲として残す」価値を画面の表現にすることであり、複数の画面に共通する表示規則が必要になる。

## Decision

HomeとMemoriesは既存Libraryルートに統合し、今日への入口と録音年月で辿る思い出を同じ画面に置く。実際の保存クリップの長さを「一日の軌跡」として扱い、実会話・歌詞・日時・場所を各段階でつなぐ。白い入口と記録、色のある完成記録を維持する。表示規則は共通のトークンと表示専用関数で定義し、既存の保存契約と非同期処理を変更しない。

HomeとMemoriesを別ルートにする案は主要な操作の移動を増やすため見送る。別々の仮写真を生成する案は未実装の写真機能を前提にし、一日の実情報を伝えないため見送る。リアルタイム会話表示と歌詞同期の演出は現在の処理・データが対応しないため採用しない。

## Consequences

- 利点: 自分たちの言葉と時間で一日を区別し、記録から曲、曲から元会話まで共通の文脈で辿れる。音声・保存・認証・料金の既存境界を保てる。
- 受け入れる欠点: 写真中心の一覧より文字を読む必要がある。日時不明や会話がない記録もあり、実情報の欠落を明示する必要がある。Web表示の検証だけではネイティブ音声・位置や実APIの受け入れを証明できない。

画面設計・適用するスキルの範囲・確認方法は[UI刷新の設計](../ui-refresh.md)を参照する。ADR0002・0003・0008・0009・0016・0017の契約は維持する。
