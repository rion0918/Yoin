# Yoin UI刷新: あの日を、辿って聴く。

Date: 2026-10-07

2026-10-08に[小さな記憶のギャラリー](premium-ui.md)として素材・構図・モーションをさらに刷新した。以下は最初の刷新時の設計記録。

## 現状と実装境界

本実装は `App.tsx` と `src/` のExpo / React Native。`prototype/` は旧デザインの操作検証用。今回、本実装の表示層を刷新し、旧プロトタイプと保護ランタイムは保持する。デザイン判断は2026-10-07のチャットでユーザーから委任された。

現在の画面はログイン、ライブラリ、参加者選択、録音、仕上げ、歌詞編集、処理状況、完成曲、元会話、設定、話者登録・編集。認証、声登録、参加者を選んだ下書き作成、録音・停止・再開、終了時の保存、場所の任意取得と編集、音声取り込み、元会話の区間再生、歌詞の編集と確認、非同期生成、完成曲の再生とシーク、ログアウト・削除を持つ。

画面は `useSession` の操作を呼び、UID別端末保存とWorker APIにつながる。マイク・位置・再生はplatform層、出典は歌詞ブロックの発話ID。文字起こしは仕上げ時でありリアルタイムではない。歌唱と歌詞の時刻同期、写真添付、自動ジャケット、地図、公開共有は存在しない。新UIで実装済みのように見せない。

## 1. 現状UIの問題点

- ライブラリのジャケットとタイトルだけでは、一日を区別する会話・人物・時間が伝わりにくい。本実装は全曲に同じ仮背景を使用する。
- 記録画面の巨大なマイク・録音時間が操作の主役。場所の説明が加わり主要操作までの距離も増えている。
- 生成はスピナーと説明であり、ユーザーが残した内容が見えない。
- 詳細には歌詞と出典があり価値の基盤は良いが、曲名とジャケットが繰り返され、元会話へ辿る入口も小さい。
- 色・文字・余白は各画面に直接定義され、季節色が記録・設定の操作色にも混在する。

ブラウザーで現行プロトタイプの入口・記録・詳細を撮影。実機の録音・生成の実行は今回のUI監査とは別。Web本実装は認証後へ進めないため、`qa/ui-refresh/preview.tsx` で同じ本実装コンポーネントを外部通信なしのサンプルデータで表示して検証する。

## 2. デザインコンセプト

**あの日を、辿って聴く。** 今日の時間を残し、その言葉を確かめ、数ヶ月後に一曲から会話まで戻ってくる。速さだけでなく「自分たちの時間が残っている」実感を優先する。AI、録音ファイル、曲一覧を主役にしない。

## 3. 独自のビジュアル言語

「一日の軌跡」を全画面の共通語にする。線上の区間は保存されたクリップを表し、長さは実際の記録時間に比例する。音量を計測した波形として扱わない。日時、場所、会話、歌詞を同じ時間の文脈へ置く。

一覧は実際の会話のひとこと（なければ歌詞の一行）と日付が一日の顔になる。詳細では歌詞を主役にし、対応する日時・場所と会話を開く操作を隣に置く。すべてをカードで囲まない。写真のない記録に別の旅行写真を充てない。

転用チェック: 一般的な音楽アプリでは、歌詞に元会話の日時・場所と出典が結びつかない。一般的な録音アプリでは、保存区間から歌詞を確かめ、一日の作品へ戻る流れがない。その関係を画面構成に残す。

## 4. 色・タイポグラフィ・余白・モーション

- 白い入口と記録、墨色の操作。完成した記録だけ既存の季節背景と落ち着いた琥珀色を持つ。既存の白基調契約を優先し、今回は別のダークテーマを増やさない。
- 日本語はプラットフォームのsystem sans。会話・歌詞は24〜32px、日時は12〜14px、操作は15〜16px。時間は等幅数字、本文は十分な行間。文字拡大時は折り返し・縦スクロールを許す。
- ページの左右24px、言葉と日時の間8〜12px、出来事の間28〜36px。押せる区間を44px以上に保つ。角丸は操作・シートに限定し、記憶そのものをコンテナへ閉じ込めない。
- DESIGN_VARIANCE 7 / MOTION_INTENSITY 4 / VISUAL_DENSITY 3。モバイルの一列の読みやすさを守り、画面ごとに構図を変える。TailwindなどWeb向けの既定スタックは持ち込まず、既存のReact NativeとAnimatedを使う。
- 押下の既存spring、画面の既存navigation、言葉の短い出現、記録状態の穏やかな反応。Reduced Motionでは出現と状態を静止で伝える。背景を動かさず、歌詞が音声に同期する演出もしない。Hapticsは未導入依存を追加せず今回の範囲外。

## 5. 主要画面

| 画面 | 構図と行動 | 使用する既存データ |
| :--- | :--- | :--- |
| Home | 白い紙面に「今日を、残そう。」と記録の入口。作りかけの一日へ戻る。HomeとMemoriesは一つの画面 | 下書き、登録済み参加者 |
| Recording | 参加者と日付、小さなマイク状態、時間の軌跡、固定した開始・停止位置、下に残した区間。位置の説明は任意の設定シートにまとめる | 保存クリップ、実録音経過、参加者、位置状態 |
| Generating | 状態に応じて保存区間→会話→歌詞を見せる。実データがなければ日時と区間を見せる。実際の状態だけを伝え、進捗率を捏造しない | DraftStatus、クリップ、発話、確認済み歌詞 |
| Memory Detail | 一日の名前、参加者と場所、歌詞に沿った縦の軌跡、元会話の入口、下端の再生操作 | 歌詞ブロック、出典発話ID、録音日時・場所、曲音源 |
| Memories | 録音した現地年月でまとまり、会話の言葉と日付が続く。生成日で並べず、日時不明は明示して残す | 実会話・歌詞、クリップ、参加者 |

名前と歌詞の確認・編集は維持する。参加者選択もADR0016に従い省略しない。位置の同意と取得条件はADR0017に従い変更しない。疑わしい文字起こしの確認、受付不明の待機、失敗からの復帰は通常の生成演出から区別する。

## 6. 既存UIから変える点

アルバムグリッドを年月と言葉の連なりへ、巨大なマイク表示を今日の時間と保存区間へ、スピナー中心の生成を実際の言葉へ、繰り返すジャケットを歌詞・出来事の関係へ変える。ルート・保存データ・音声エンジン・API・認証・課金制御の契約は維持する。

## 完了確認

録音年月・未知の日時・会話と歌詞の優先・場所の重複除去をRED→GREENで検証。新規記録→参加者選択→開始・停止・再開→仕上げ、および詳細→元会話・再生・シークをサンプルで確認。狭い画面、短い画面、長い文字、空の一覧、生成・失敗・照合待ちも確認する。Nix内のBiome、TypeScript、既存テストを実行する。実機・実API品質は成功扱いしない。
