# プロダクト仕様

[ドキュメントの目次](README.md)へ

Yoinは、残した会話を確認・編集した歌詞から曲にし、元の会話と一緒に聴き返すアプリです。この文書は現在の実装の振る舞いを説明します。実際に確認できた範囲は[検証記録](audio-pipeline-verification.md#現在の確認状況)を参照してください。

## 録音から曲まで

| 操作 | 振る舞い |
| :--- | :--- |
| 初回にアプリを開く | Googleでログインし、名前と声の登録へ進む。登録済みなら本人のライブラリを開く |
| 話者を登録する | 名前入力後に録音の案内を表示し、利用者が「録音を始める」を押して約20秒録音する。録音中は残り時間、停止後は試聴・録り直し・登録を表示する。短い音声は録り直しへ案内し、サーバー登録の成功後に完了を表示する。少なくとも1人の登録完了後に会話録音を開始できる |
| ライブラリで記録を作る | 登録済み話者がいない場合は話者登録へ案内し、登録済みなら新しい下書きを開く。ライブラリと録音画面は白を基調にする |
| 録音を開始・停止・再開する | 停止ごとに音声ファイルを確定し、再開は新しいファイルを同じ下書きへ追加する |
| 話者設定を変更する | 同行者の追加、登録名変更、声の録り直し、削除を行う。登録済みならオフライン録音できる |
| 録音画面から戻る | 録音中なら停止・保存を待つ。保存済み会話がある下書きは再開できる。音声も復旧対象もない空の下書きは破棄する |
| 音声を取り込む | 選んだ音声を端末内へコピーし、実時間とサイズを取得する |
| 仕上げる | 名前と音声を確認し、必要なら区間の場所を手入力する。送信後は文字起こしと出典付き歌詞案を準備する |
| 歌詞を確認・編集する | 元発話との対応を保持して歌詞を修正する。編集したリビジョンを曲生成に使用する |
| 曲を生成する | 保存された実音源を持つ曲をライブラリへ追加する。完成した曲の画面に色と背景を持たせる |
| 曲と会話を聴き返す | 歌詞の会話アイコンから元の会話区間を聴き、曲の再生位置を保持して戻る |

仕上げ中の下書きには録音や音声を追加できません。名前や音声がない状態では仕上げられません。設定にはログイン中のアカウント、話者管理、ログアウト、アカウント削除を表示します。API接続先はビルド時に固定します。完成曲の閲覧・再生は話者未登録でも利用できます。

## 元会話との対応

- 文字起こしは音声ID、仮話者ラベル、元ファイル内の開始・終了時刻を持つ。登録プロフィールへ十分な確度で一致した発話にはプロフィールIDと登録名を保存する。
- 歌詞ブロックは元発話IDを保持する。存在しない元発話を出典にできない。
- 話者名は利用者が登録した声との照合だけで表示し、人名を自動推測しない。十分な音声がない・候補が曖昧・未登録の声では仮ラベルを保持する。
- 既存の保存済み文字起こしと完成曲は再識別しない。
- 元会話の時刻と曲の再生位置は別々に扱う。歌詞と歌唱の時刻同期・歌詞ジャンプは現在の範囲に含まない。
- 出典が存在しても、歌詞の意味や実際の歌唱の一致は[品質評価](internal-testing.md#品質評価)で確認する。

## 日時と場所

録音開始日時と取り込み日時を別に保持します。取り込んだ音声の録音日時が不明なら、不明のまま扱い、ファイルの更新日時から補いません。表示する元会話の日時は録音日時・タイムゾーン・発話のオフセットから求めます。

場所は仕上げ前の手入力です。未指定は不明のまま扱い、GPSによる自動取得は実装していません。

## 入力と録音の制約

| 項目 | 上限・扱い |
| :--- | :--- |
| 生成へ送信する音声 | 下書きの合計60分以内 |
| 1ファイル | 100MiB以内 |
| APIが受付する形式 | MP4/M4A、MP3、WAV、AACの対応MIME形式。実ファイルをFFmpegで検査する |
| 送信 | 8MiB単位のmultipart。進行を保存して途中から再開する |
| 文字起こしの前処理 | モノラル16kHz・AACへ変換し、約25分単位に分割する（エンコード境界で最大1秒の許容） |

60分は生成入力の上限で、自動録音停止の時間ではありません。上限を超えた音声も端末に保持しますが、生成への送信は拒否します。

画面ロックや他アプリへの移動では録音を継続する設定です。通話などの割り込みは中断として扱い、自動で録音を再開しません。強制終了後は実ファイルを検査して復旧しますが、未確定・壊れた音声の復元は保証できません。

## 保存と失敗時の扱い

Firebase UIDごとのDocuments領域に会話音声と話者登録音声を保存し、UIDごとのSQLiteに下書き・話者プロフィール・歌詞・ジョブ等を保存します。録音中の未確定ファイルは本人のSQLiteで参照し、停止・復旧時に本人の領域へ移します。ログアウトは録音停止・保存、再生・通信の終了を待ちます。同じUIDで再ログインすると端末の下書きとサーバーの曲・話者を復元します。旧開発データは隔離して保持し、新しい利用者へ自動移管しません。送信・生成が失敗しても元音声の参照を保持します。読み取れない録音候補は復旧対象として残し、起動時に用途を分けて再検査します。アプリ削除後の復元や端末間同期は現在の範囲に含まれません。

生成処理はサーバーのジョブとして継続し、アプリを開き直すと保存された状態を取得します。有料APIの受付結果が不明なら照合待ちで停止します。再生成の連打による重複課金を避ける契約は[構成・設計](audio-pipeline-architecture.md#有料試行と結果回復)を参照してください。

## アカウント削除

設定から確認後、Googleで再認証して削除を要求します。受付後に本人の端末データを消去し、サーバーのWorkflowが処理履歴・会話・歌詞・曲・話者・音声・特徴量・Firebaseアカウントを削除します。受付不明なら端末データを残し、次回起動で状態を確認します。削除中は新規処理・再生・コールバックを拒否し、削除済みUIDは24時間拒否します。全利用者共通の費用台帳は、個人情報を含まない費用・試行状態を保持します。再登録で予算を初期化しません。

実サービスの削除、実機とPlay配布は[検証記録](audio-pipeline-verification.md)で実装・モック確認と分けて記録します。

## 対応端末と提供範囲

| 対象 | 用途 |
| :--- | :--- |
| Android Google Play内部テスト | store配布のAABから導入。Metroや開発PCなしで録音・取り込み・保存・生成・再生を確認する |
| Android development build | 開発用。Metro接続が必要 |
| Web | 画面・操作の確認。ネイティブ録音・端末音声の取り込みは無効 |
| iOS | コードとexportの対象。iPhone実機での受け入れは未完了 |

GoogleのFirebase IDトークンで本人を識別し、検証済みメールの許可リストにある利用者だけを受け付けます。サーバーもUIDごとにデータを分離します。公開共有、利用者への課金、自動ジャケット生成は実装していません。AIモデルは品質検証候補で、完成品としての品質・商用利用可能性の確認は残っています。
