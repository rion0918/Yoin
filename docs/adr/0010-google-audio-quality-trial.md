# ADR 0010: Google APIを累積10ドル以内の音声品質検証候補に採用する

Date: 2026-10-04

## Status

Accepted

採用確認: 2026-10-04 のチャットで、ユーザーがGoogle APIによる品質検証と累積10ドルの試行予算を含む実装計画に対して「IMPLEMENT THIS PLAN」と指示した。

このAcceptedはPoC候補と検証方法の採用を表す。日本語の品質、料金の実測、商用条件、製品への本採用は未検証である。

## Context

アプリの価値は、旅行の実会話を正しく捉え、利用者が確認した歌詞を音楽として聴き返せることにある。サンプル歌詞や生成物の返却だけでは、話者・時刻・固有名詞の正確さや、歌った言葉と承認した歌詞の一致を判断できない。

外部APIのタイムアウトでは処理や課金の成否が不明になる。試行ごとに予算を初期化したり、同じリクエストを自動再送したりすると、意図した試行費用を超える可能性がある。

## Decision

Googleの文字起こし、歌詞作成、音楽生成APIをPoC候補に使用する。[アダプター](../../pipeline/google.ts)で呼び出しを分離し、[文字起こし](https://ai.google.dev/gemini-api/docs/transcribe)、[音楽生成](https://ai.google.dev/gemini-api/docs/music-generation)、[料金](https://ai.google.dev/gemini-api/docs/pricing)の公式仕様を実行前に確認する。

短い日本語の複数人会話を実APIへ入力し、文字起こしの言葉・話者・区間時刻・固有名詞を元音声と比較する。歌詞ブロックから元の発話IDを保持し、利用者による確認・編集後のリビジョンを曲生成へ渡す。返された歌詞テキストを照合し、生成音声を実際に聴いて脱落・追加・読み違いを評価する。テキストの一致だけで、歌唱の一致を合格としない。

試行のAI費用は累積10ドル以内の予算として管理する。外部呼び出し前に入力の指紋と予約額を永続化し、利用量からの料金見積もりを記録する。未確定の予約は支出として数える。同じ試行の保存済み結果は再利用し、送信済みで結果が不明なら照合待ちで止める。Workflowの有料ステップも自動再試行しない。実料金見積もりが予約額を超えた場合は、新しい呼び出しを止める。

[ローカル台帳](../../pipeline/budget.ts)から[クラウド台帳](../../backend/paid.ts)へ移す際は、確定費用と未確定予約を差し引いた残額だけを引き継ぎ、ローカル側の新規呼び出しを閉じる。各環境で10ドルずつ使える運用にしない。これは予約に基づくアプリ側の制御であり、プロバイダー請求の厳密な上限保証ではない。Cloudflareなどの基盤料金は別に扱う。

検証にはffmpeg / ffprobeをNix開発環境と[メディアコンテナー](../../backend/media/Dockerfile)へ追加する。入力・生成音声の実時間を測り、長い音声を25分以内の区間へ分割して時刻オフセットを保持するためである。録音画面側に未検証の自動分割を追加せず、非同期の文字起こしで処理する。

## Consequences

- 利点: 実際の会話と承認した歌詞を基準に候補を比較できる。時刻・発話・歌詞リビジョン・生成音声を追跡し、重複課金を避ける制御を持てる。
- 受け入れる欠点: モデルや料金・利用条件が変わり得る。予約額の見積もりが不足する可能性があり、結果不明の試行は自動でやり直せない。実APIの鍵、入力音声、試聴による評価が必要になる。

品質と商用条件を確認するまで、本番品質や商用利用可能な完成品とは扱わない。品質ゲートに届かない場合は、本採用前に別候補または体験の変更を検討する。
