# 内部テスト

[ドキュメントの目次](README.md)へ

Google Playから導入したAndroid配布版で、Googleログイン → ライブラリ → 話者設定または「＋」から名前と声を登録 → 録音・取り込み → 歌詞確認・編集 → 曲生成 → 再生を確認します。初回ログイン後は登録画面を自動で開かず、ライブラリを表示します。[配布準備](play-internal-release.md)と[検証記録](audio-pipeline-verification.md)を参照してください。

## 開始条件

- 配布AAB、Firebase設定、署名証明書、Worker・Cloud Runへの反映が完了している。
- 許可リストへ登録された検証済みGoogleアカウントを2つ用意する。
- Google Play内部テストの招待からアプリを導入する。Metro・USB・開発PCへの接続を外して起動する。
- 実AI確認の前には運用側が累積予算・未確定予約を照合する。利用者に接続先・トークン・予算・実行履歴の入力や確認を要求しない。
- ビルド・署名・端末・操作条件を記録する。開発版の導入は[README](../README.md)、ローカル接続は[配布準備](play-internal-release.md#firebasegoogleeasの準備)を参照する。

## Androidへの導入と接続設定

Playから導入したアプリでは接続設定はありません。Googleログインをキャンセルするとログイン画面に残り、アカウントを選ぶと本人の領域だけを開きます。Firebase・許可リストの不足や署名不一致は運用側で確認します。ビルド成功だけをGoogleログイン・録音・再生の成功として記録しません。

## アカウント分離と削除

| シナリオ | 期待する結果 |
| :--- | :--- |
| Aで下書き・曲・話者を作り、ログアウトしてBへ切り替える | Bの一覧・端末保存・話者にAのデータがない。ログアウトは録音停止・保存を待ち、再生・通信・ポーリングを終了する |
| BでAの下書き・曲・音声・ジョブ・話者のIDを指定する | 取得や更新を拒否する。音声の再生URLを取得できない |
| Aで再ログインする | Aの端末下書きとサーバーの曲・話者が復元される。Bの保存内容と混ざらない |
| 切り替え前のAPI応答を遅延させる | 切り替え後の表示・SQLiteへ反映しない |
| 旧開発データがある端末で初回ログインする | 旧データを新UIDへ自動移管しない |
| 削除確認やGoogle再認証をキャンセルする | 削除しない。録音・下書き・曲・声を保持する |
| 削除受付前・受付応答中に通信を切断する | 未受付なら保持する。受付不明なら次回ログインで状態と同じ削除を確認する |
| 生成中に削除する | 新規処理・コールバックを拒否し、Workflow履歴・D1・R2・Firebaseユーザーを消す |
| 削除途中でCloud RunやR2を失敗させて復旧する | 同じWorkflowで再開し、本人のデータだけを削除する |
| 削除済みIDトークン・既存署名URL・遅延コールバックを送る | 拒否し、削除したデータが復活しない |
| 削除と再登録後に台帳を比較する | 実費・未確定予約が残る。利用人数やUID変更で予算がリセットされない |
| 削除完了24時間後 | 拒否記録と削除Workflow自身の状態が消える。期限切れの旧トークンは拒否される |

APIと端末の両方を確認します。署名URLは本人が取得する期限付きの参照として扱い、公開しません。

## 短い会話で一度完走する

最初に話者設定を開き、自分と同行者2人の名前を登録します。各人について約20秒話して録音し、試聴後に登録します。無音・短い音声では登録できません。登録音声は会話下書きへ追加されないこと、登録後にアプリを再起動してもプロフィールが残ることを確認します。次に3〜5分程度の2人の日本語会話を録音し、登録した人同士の別内容の会話でも名前が表示されることを確認します。十分な長さの発話は90%以上の正答、確認用の未登録話者には登録名を付けないことを記録します。保存済み文字起こし・完成曲の再識別は対象外です。

| 操作 | 期待する結果 |
| :--- | :--- |
| 未登録状態で＋を押す | 録音を開始せず、話者登録へ案内する |
| 2人の名前と声を登録する | 名前入力の「次へ」だけでは録音が始まらない。「録音を始める」で開始し、残り時間を確認して停止・試聴・登録へ進む。完了表示が出て、再起動後も登録名が残る。登録音声は会話下書きに現れない |
| 登録UIで短い録音を確認する・録音中に閉じる | 短い音声は登録へ送らず録り直しを案内する。録音中に閉じる場合は停止と保存を待ち、再び開くと保存した音声を確認できる |
| ＋から記録を作る | 登録後は空の下書きが開き、オフラインでも録音を開始できる |
| マイク権限を許可し、開始→停止→再開→停止 | 音声区間が残り、同じ下書きへ追加される |
| 別試行で端末音声を取り込む | 実時間・サイズが表示される。録音日時が不明なら不明のまま |
| 戻る→下書きを開き直す | 保存済み会話が保持される |
| 仕上げ前に場所を入力し、名前と音声を確認して仕上げる | 元音声が送信され、準備ジョブの状態を確認できる |
| 歌詞案を確認し、1ブロックを編集する | 元発話IDとの対応を保ち、編集した版が保存される |
| 曲生成を要求する | 確認済みの版を使う。実音源のある曲がライブラリに追加される |
| 完成曲を最後まで再生・シークする | 実音声が聴け、位置を変更できる |
| 歌詞の会話アイコンから元会話を再生し、曲へ戻る | 正しい元音声区間と日時・場所が表示され、曲の位置が保持される |

予算0の場合は準備が `ai_budget_exhausted` で停止し、音声を保持して停止状態を表示することを期待します。生成成功の項目は未実施として記録します。

## 長時間録音・中断・復旧

| シナリオ | 確認すること |
| :--- | :--- |
| 連続60分録音 | 保存後の実音声が最後まで再生できる。生成入力の合計上限と一致する |
| 画面ロック・他アプリ使用 | 録音が継続し、通知から停止して保存できる |
| 通話などの割り込み | 中断が認識され、勝手に録音を再開しない。残った音声を確認できる |
| 録音中の強制終了 | 再起動で録音中表示を復元せず、実ファイルを検査する。回収できなかった参照を失わない |
| 保存後の再起動 | ログイン状態と本人の下書き、音声、編集歌詞が残る |
| オフライン録音 | 停止・保存ができ、通信復帰後に送信できる |
| 送信途中の切断 | 保存されたmultipart進行から再開する |
| 生成中のアプリ終了 | 再起動で同じジョブの状態・完成曲を取得する |
| 操作の連打・応答喪失 | 同じ要求を重複課金・二重登録しない |
| 上限超過・不正認証・旧歌詞版 | 拒否理由を確認でき、元音声を失わない |
| 有料APIの受付不明 | 照合待ちで停止し、予約を保持する。試験のために有料POSTを繰り返さない |

復旧対象の参照保持は、音声の復元成功とは区別して記録します。歌詞同期・歌詞ジャンプはテスト対象に含めません。

## 品質評価

- 文字起こし：言葉、登録名または仮の話者、区間時刻、地名・人名などの固有名詞を元音声と比較する。チャンクごとの `spk_1` が別人物でも誤って同一視しない。
- 歌詞案：会話にない出来事・情景を追加していないか、誰が何をしたか、伝聞か本人の体験かを照合する。
- 編集歌詞：出典IDが実在する発話を指し、編集後の版が生成へ渡っているか確認する。
- 生成曲：最後まで聴き、言葉の脱落・追加・読み違いと承認した歌詞の歌唱を確認する。
- 条件差：2人、3人、雑音あり、旅行会話で試し、試した条件と問題を記録する。
- 話者識別：各登録者の別内容発話で正答率を測る。候補が似る会話、短い発話、未登録話者で誤った名前が付かないかも記録する。

返却歌詞のテキスト一致やAPI成功だけを、実際の歌唱品質の合格としません。ローカルPoCの保存ファイルとコマンドは[PoCと試聴](audio-pipeline-setup.md#ローカルpocと試聴)を参照してください。品質・商用条件を確認するまで、候補モデルの本採用を確定しません。

## 結果と不具合を記録する

1回の確認ごとに、次を記録して[検証記録](audio-pipeline-verification.md)へ反映します。

```text
確認日・確認者:
ビルドのコミット / バージョン:
端末・Androidバージョン:
接続先・AI予算の有効化状況:
音声の長さ・人数・雑音などの条件:
シナリオと再現手順:
期待した結果:
実際の結果 / 合格・不合格・未実施:
下書きID・ジョブID / エラーコード:
証拠の保管場所と未確認事項:
```

録音・個人情報・認証情報・期限付きURL・Googleの生応答を公開の不具合本文へ貼りません。必要な証拠は非公開の保管場所を参照します。受付不明の有料処理は[運用手順](audio-pipeline-setup.md#障害と結果不明の確認)で照合し、再試行で問題を隠さないでください。
