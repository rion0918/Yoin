# ADR 0031: 思い出単位の削除を永続記録と非同期処理で行う

Date: 2026-10-13

## Status

Proposed

## Context

思い出のデータは端末のSQLite・音声ファイルと、Cloudflare D1・R2・Workflow履歴に分散している。削除要求と並行して処理が完了すると、遅れて届いた応答や保存処理から対象データが再作成される可能性がある。応答を受け取れない場合やアプリ・Workflowが停止した場合にも、受付状況を照合し削除を再開する必要がある。

## Decision

削除単位を `draftId` とし、端末とD1の双方に削除記録を残して、D1の所有者別 tombstone と専用Cloudflare Workflowで非同期に消去する。受付後は読み書きと同IDの再作成を拒み、一覧から除外する。Workflowは既存ジョブの実行・履歴を停止・削除してから、対象に属する音声・応答・位置情報・D1データを消去する。費用と受付不明の予約額は思い出データと独立しているため保持する。

複数の永続層を一つのHTTP要求内で同期消去する方法では、部分失敗や応答喪失後の進捗を再開しにくいため採用しない。アカウント削除では同じ削除Workflowを停止してから、従来どおりアカウント全体を消去する。

## Consequences

- 利点: 応答喪失やプロセス終了後にも状態を照合でき、遅延書き込みで削除済みデータが復活するのを防げる。削除を所有者と `draftId` に限定できる。
- 受け入れる欠点: サーバー側の完全消去は非同期であり、受付後もしばらく削除中として表示する。失敗した削除記録は再試行のため保持する。

Cloudflare Workflowのインスタンス・履歴削除は[公式仕様](https://developers.cloudflare.com/workflows/build/workers-api/)に従う。
